# Testing and packaging

From the repository root:

```sh
python3 -m unittest discover -s tests -v
bash -n install.sh
git diff --check
```

The tests cover process identity and safe signaling, keyboard/touch controls,
small windows, mouse-wheel navigation, CLI errors, installer paths, destination
conflicts, settings preservation, repeat installs, atomic
writes, and launcher lifecycle/concurrency. Apps tests cover XDG data homes,
first-time directory creation, desktop ID/permissions/visibility, unrelated
entries and installer refresh guidance.

Optional checks report explicit skips when dependencies are unavailable:

- `desktop-file-validate` checks the generated desktop entry.
- `qs` runs a fresh native registry with the widget disabled and executes the
  entry against a harmless stub. It does not inspect an already-running shell or
  verify the real task-manager window.
- Node.js and the actual Omarchy shell source exercise its Apps search/filter code:

  ```sh
  OMARCHY_SHELL_DIR="$OMARCHY_PATH/shell" python3 -m unittest discover -s tests -v
  ```

  Set `OMARCHY_SHELL_DIR` to the directory containing `services/AppSearch.js`;
  for a source checkout this is typically `desktop/shell/shell`.

## Device checks

Automated tests do not replace physical iPad menu/bar/touch validation. Test
installation from SSH and an on-device terminal, preserving existing settings
and applications. For Apps discovery, check before and after a full Quickshell
restart, including a custom XDG data home when applicable; see
[troubleshooting](troubleshooting.md).

With the widget disabled, select Resource Monitor in Apps and verify the window
and widget appear. Close with X: only the window should stop. Reopen from the
widget, then press q or tap Quit: both should stop while Quickshell and unrelated
apps remain running. Check Escape cancellation versus window close, q during a
confirmation, reopening after a crash, rapid repeated launches, and touch/scroll
controls at small window sizes. Record the tested commit and actual results.

The launcher uses a per-user/session file lock, retained until Foot exits and
Quit cleanup completes. The lock file remains on disk; an unlocked stale PID
cannot block a new launch. A private per-launch quit request distinguishes
explicit Quit from a window close or crash. Focus checks both Foot's PID and app
ID, and never signals a stored PID.

## Contributing

Keep changes focused and include a regression test for behavior changes. Use
only the Python standard library at runtime. Preserve the process-identity
checks, per-session launch lock, and distinction between closing a window and
quitting both components. For UI changes, include results from a device check;
the mocked terminal tests cannot establish QML rendering or touch behavior.

## Package

Create a source archive without generated bytecode:

```sh
git archive --format=tar.gz --prefix=resource-monitor/ \
  -o resource-monitor.tar.gz HEAD
```
